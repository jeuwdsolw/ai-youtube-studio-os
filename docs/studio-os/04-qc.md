## Швидкий режим (за замовчуванням з 2026-11-24, рішення власника)
`[qc] max_rounds = 1`: **циклу переробок немає.** QC виконується один раз, звіт і задачі (`fix_tasks` = `human`) ідуть на етап
`approval`: власник бачить вердикт і вирішує. Відео з NEEDS_REVISION/REJECTED публікується лише після **ручного** погодження
(автопогодження — тільки для APPROVED*). **BLOCKED_CRITICAL** (зламаний файл, чорний екран, тиша) блокує завжди → `qc` = `needs_human`.
Разом із `[production] strict_checks = false`: агентні сесії не ганяють перевірки по колу — motion_check/check_video/check_storyboard
запускає конвеєр один раз (без токенів), знахідки стають попередженнями; сценарій переробляється лише через структурні помилки
(ID/seq реплік, голос поза `narrator_only`, порожній текст). Чому: один раунд QC r1 на еп. 019 повернув відео на сценарій і
перезапустив script → voice → storyboard → animation (35 хв) → edit.

## Цикл виправлень (`max_rounds` > 1)
QC не пройдено → задачі (critical/major) у `fix_tasks` → найраніший етап-виконавець отримує зауваження
«доопрацювати: QC rN — <план/секунда>: <проблема> (приймання: <критерій>)» → повтор етапів до QC (обкладинка — лише якщо є задача
на неї або змінено сценарій) → новий раунд. Після `[qc].max_rounds` — звіт на погодження (критичні → `needs_human`).
Якщо виправлення торкається сценарію, агент голосу сам переносить застаріле аудіо в `audio/raw/old-<час>/` (нічого не видаляє)
і перегенеровує лише змінені блоки (мітка `<блок>.src.sha1`; аудіо епізодів власника без мітки не чіпає).

Звіт кожного раунду: `<епізод>/qc/qc-rN.md` + `.json`; таблиці `qc_reports`, `fix_tasks`.

## Погодження й публікація
- `approval`: semi — фінал погоджує людина; auto — автопогодження лише при QC APPROVED/APPROVED_WITH_WARNINGS;
  публікація без погодження людини — тільки якщо `auto_publish = true` (зараз false у всіх режимах).
- `publish` без QC-проходу й погодження неможливий (`can_publish`). Агент публікації — Етап 5.
