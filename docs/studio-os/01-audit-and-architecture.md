## 1. Що вже є (результат аудиту)

Студія — не порожній проєкт, а робочий виробничий конвеєр, на якому вже зроблено 18 Shorts і 6 Long (частина в роботі).

| Область | Стан | Де |
|---|---|---|
| Візуальний стиль | **затверджений і формалізований**: біблія, палітра v2 (JSON), правила розкадровки, еталон обкладинок | `channel/` |
| Персонажі | ≈ 50 персонажів (канон + чернетки), JSON-канон + вирази + SVG-риги + аркуші | `channel/characters/`, `video/src/two-d/rig/` |
| Локації | ≈ 20 локацій, кожна — одна модель у метрах + референс-кадри | `channel/locations/` |
| Анімація | Remotion 4.0.539 + SVG cutout-риги, бібліотека поз, шаблони планів, хода; Blender 5.2 для 2.5D | `video/src/`, `scripts/blender/` |
| Голос | ElevenLabs API (ключ у `.env`, тариф Creator), автонарізка реплік, темп 140 сл/хв; Piper/Edge — запас | `scripts/audio/`, `tools/tts-venv` |
| Звук | процедурні SFX (власні, без ліцензій), мікс, мастер −14 LUFS | `scripts/audio/` |
| Монтаж | `edit.json` → Remotion; SRT-експорт; нарізка Shorts із Long (`психлікарня/shorts.json`) | `scripts/`, `video/src/episodes/` |
| QC (автоматика) | `check_video.py` (формат, гучність, статичні секунди), `check_storyboard.py`, `motion_check.mjs` (STATIC/HOLD), `audit_text.mjs`/`board_check.mjs` (межі написів) | `tests/`, `video/scripts/` |
| Пакет YouTube | `youtube.md` на епізод (3 назви, опис, теги, налаштування) — **вручну** | `episodes/<ep>/youtube.md` |
| Процес | Claude Code + скіл `studio-animation`, затвердження власником по сценах | `CLAUDE.md`, `.claude/skills/` |

**Чого немає:** дослідження трендів, контент-плану й календаря, бази даних, оркестратора, черги задач, планувальника,
інтеграції з YouTube Data/Analytics API, дашборду, централізованого журналу, автоматичного циклу «QC → виправлення».

### Ключові висновки аудиту
1. **Стиль тримається кодом, а не промптами.** Персонажі — параметричні риги, кольори — з `palette.json`. Це головна перевага:
   візуальна консистентність гарантується конструктивно. **Тому AI-генерація зображень/відео (Kling, Runway, Midjourney тощо)
   не повинна бути основним шляхом анімації** — вона зламала б упізнаваність. Вона лишається вимкненим опційним адаптером.
2. **«Аніматор» — це Claude Code, що пише TSX-плани.** Кожен епізод зараз — унікальний код (`ep0NN/sc*.tsx`) + власні
   `eNN_*_build.py`. Автономія можлива лише якщо (а) Claude Code запускається безголово (`claude -p`, встановлено) і
   (б) повторювані скрипти узагальнюються в спільні модулі.
3. **Пропускна здатність — головний ризик.** 7 Shorts + 3 Long на тиждень ≈ ×5–10 від поточного темпу (Long «Медогляд»:
   234 плани, кілька сесій, зупинка на ліміті використання). Без нарізки Shorts із Long і шаблонів планів план нереальний.
4. **Диск C: 97 % зайнято (≈ 30 ГБ вільно).** Рендери й PNG-послідовності швидко його заповнять → потрібна політика зберігання.
5. **Немає Docker, Redis, PostgreSQL, прав адміністратора.** Архітектура має працювати на чистому Python + SQLite + Node.
6. Наявні Long — 13–15 хв (формат «посібник виживання»); у новому ТЗ орієнтир 6–12 хв → потрібне рішення власника.

## 2. Архітектура

```
                         ┌──────────────────────────── Dashboard (React + Vite) ───────────────────────────┐
                         │ Overview · Calendar · Pipeline · QC · Analytics · Settings · Approvals · STOP   │
                         └───────────────────────────────▲─────────────────────────────────────────────────┘
                                                         │ REST (FastAPI, localhost)
┌────────────────────────────────────────── ORCHESTRATOR (Python, один процес) ──────────────────────────────────┐
│ Scheduler (zoneinfo Europe/Kyiv, DST) → Job Queue (SQLite, leases, retries, resource locks) → Agent Runner      │
│ Budget Guard (ліміти ElevenLabs/API/LLM) · Approval Gates (режими 1/2/3) · Kill-switch · Event Log · Backups     │
└───────┬──────────┬──────────┬──────────┬──────────┬──────────┬──────────┬──────────┬──────────┬────────────────┘
        │          │          │          │          │          │          │          │          │
   1 Trend    2 Strategist 3 Script  4 Storyboard 5 Animation 6 Voice&  Edit/    7 QC      8 Publish   9 Analytics
   Research                                                  Sound    Assemble  (8 модулів)
        │                                    │          │          │          │          │          │
        ▼                                    ▼          ▼          ▼          ▼          ▼          ▼
  ┌───────────── Adapters (змінні, кожен з health-check) ─────────────────────────────────────────────────────┐
  │ LLM: ClaudeCodeHeadless | AnthropicAPI      Render: Remotion | Blender | FFmpeg      Voice: ElevenLabs | Piper │
  │ Data: YouTubeData | YouTubeAnalytics | Reddit | Trends     Image/Video AI: (вимкнено, лише зі style-gate)       │
  └───────────────────────────────────────────────────────────────────────────────────────────────────────────┘
        │
        ▼
  Файли епізодів (як зараз: episodes/<ep>/…, video/src/episodes/…) + SQLite (стан, історія, метрики)
```

### 2.1 Принципи
- **Обгортка, а не переписування.** Агенти викликають наявні скрипти й перевірки (`pipeline.py`, `voice_timeline.py`,
  `motion_check.mjs`, `check_video.py`, `master.py` тощо). Робочі модулі не переписуємо; дублікати `eNN_*_build.py`
  поступово зводимо до параметризованих загальних скриптів (з тестом «результат той самий»).
- **Файли — джерело правди для творчого вмісту** (сценарій, розкадровка, код планів — у git); **БД — для стану й історії**
  (статуси, задачі, оцінки, метрики, журнал). Так зберігається нинішній робочий процес і можна працювати вручну.
- **Кожен агент — чистий контракт:** `input` (pydantic-модель) → `output` (pydantic-модель + файли-артефакти) → події в журнал.
  Агент ніколи не «мовчки пропускає» етап: або результат, або помилка з причиною й статусом `BLOCKED`.
- **Ідемпотентність і відновлення:** задача має ключ (`episode/stage/version`), артефакти пишуться атомарно (tmp → rename),
  після перезапуску незавершені задачі з простроченою «орендою» повертаються в чергу.
- **Ресурсні замки:** `remotion` (один рендер — спільний порт 3000), `gpu` (Blender), `elevenlabs` (квота), `claude` (ліміт сесій).

### 2.2 Технологічний вибір
| Потреба | Вибір | Чому / що відкинуто |
|---|---|---|
| Агентна логіка | Python 3.12 (наявний) | уже вся студія на Python |
| Сховище | **SQLite (WAL)** + щоденна копія | без сервера й прав адміна; PostgreSQL — надмірно для 1 машини |
| Черга задач | **власна черга на SQLite** (lease + retry + backoff) | Redis/Celery/Temporal потребують сервісів/Docker, яких немає |
| Розклад | `zoneinfo` + `tzdata`, правила в `config/schedule.toml` | коректний перехід літо/зима; часовий пояс — налаштування |
| Автозапуск | Планувальник завдань Windows (рівень користувача) | без прав адміністратора |
| API дашборду | FastAPI + uvicorn (localhost) | легкий, типізований |
| Дашборд | React + TypeScript + Vite (Node 24 є) | ТЗ; графіки — Recharts |
| LLM | адаптер: **Claude Code headless** (`claude -p`, вже встановлено, скіли проєкту) / Anthropic API (за ключем) | див. §5 |
| Конфіг | TOML (`tomllib` — у стандартній бібліотеці) + `.env` для ключів | без зайвих залежностей |
| Тести | pytest (Python), наявні node-перевірки | ТЗ: тест на кожен модуль |

Нові Python-залежності (в окремий `tools/studio-venv`): `fastapi`, `uvicorn`, `pydantic`, `httpx`, `tzdata`,
`google-api-python-client`, `google-auth-oauthlib`, `pytest`. Опційно для QC стилю: `open_clip_torch` (локально на RTX 3060).

## 5. LLM: два способи, потрібне ваше рішення

| | Claude Code headless (`claude -p`) | Anthropic API (ключ) |
|---|---|---|
| Вартість | у межах наявної підписки | оплата за токени |
| Обмеження | спільні ліміти використання з вашою роботою (уже траплялася зупинка «ліміт використання») | ліміти швидкості API, бюджет у Budget Guard |
| Сильне | пише й перевіряє код планів зі скілами й `CLAUDE.md` | передбачувано для коротких текстових задач (скоринг, QC тексту) |
| Рекомендація | **анімація, розкадровка, сценарії** | **скоринг тем, QC-рецензії** — опційно, якщо захочете розвантажити підписку |

Рекомендація: почати лише з Claude Code headless (без нових витрат), API підключити пізніше як адаптер.

## 6. Розклад і календар

`config/schedule.toml` (зберігає локальний час + часовий пояс; UTC обчислюється в момент планування → DST коректно):

| День | Shorts | Long |
|---|---|---|
| Пн | 18:00 | — |
| Вт | 18:00 | 17:30 |
| Ср | 18:00 | — |
| Чт | 18:00 | 17:30 |
| Пт | 18:00 | — |
| Сб | 11:00 | 17:30 |
| Нд | 11:00 | — |

Виробничі дедлайни (зворотний відлік від публікації, налаштовується): тема −14 д, сценарій −10 д, голос −8 д,
розкадровка −7 д, анімація −4 д, QC −3 д, погодження −2 д, upload (private + `publishAt`) −1 д.
Невстигання → попередження на дашборді, а не «поспіхом зроблене» відео. Без QC=APPROVED + погодження відео не публікується.

Поля відео в БД: дата/час публікації, тип, тема, пріоритет, статуси сценарію/анімації/озвучення/монтажу, QC-результат,
погодження, публікація — точно як у ТЗ.

### Як реально вийти на 7 + 3 на тиждень (пропозиція)
- **3 Long × 2–3 Shorts-нарізки** (уже відпрацьовано на «Психлікарні»: 4 Shorts з одного Long) = 6–9 Shorts без нової анімації.
- Оригінальні Shorts — 1–3 на тиждень, на шаблонах планів (`plans.tsx`) і наявних локаціях.
- Long 6–12 хв замість 13–15 хв — менше планів.
- Нарощування поетапно: тиждень 1–2 — 1 Long + 3–4 Shorts; далі — за фактичною пропускною здатністю (дашборд її покаже).

## 8. Інтеграції: що потрібно

| Інтеграція | Вартість | Що потрібно від вас | Примітки (підтвердити по документації на відповідному етапі) |
|---|---|---|---|
| YouTube Data API v3 | безкоштовно, квота за замовчуванням 10 000 од./добу | проєкт у Google Cloud, OAuth-клієнт (Desktop), вхід власника каналу | `search.list` дорогий (≈100 од.) → кешування. **Завантаження з неперевіреного API-проєкту стають приватними**, доки проєкт не пройде аудит Google — потрібна заявка на аудит перед автопублікацією |
| YouTube Analytics API | безкоштовно | той самий OAuth (scope `yt-analytics.readonly`) | лише власний канал; частина метрик Shorts може бути недоступна через API — перевірити |

| Remotion | безкоштовно для фізосіб / до 3 працівників | — | для більшої команди — комерційна ліцензія |

## 11. Рішення власника (2026-11-23)

1. **LLM — лише Claude Code у межах підписки.** Anthropic API не підключаємо (адаптер не будуємо, доки не попросите).

   жорсткого діапазону немає.
